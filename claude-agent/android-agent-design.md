# 📱 안드로이드 기기 제어 에이전트 설계 문서

스마트폰 화면의 요소를 인식하고 사람처럼 터치·스크롤하는 **기기 제어 에이전트**를 만드는 설계입니다.
이 문서는 **설계도**입니다. 이 폴더의 파이썬 예제(`agent.py`)가 "LLM이 도구를 호출 → 코드가 실행 → 결과를 다시 LLM에게" 라는 같은 반복 구조를 보여주므로, 먼저 그 코드를 이해하면 이 설계가 훨씬 쉽게 읽힙니다.

> ⚠️ **합법적인 범위에서만.** 자신의 기기, 또는 명시적으로 허락받은 기기에서만 사용하세요.
> 또한 앱을 자동으로 조작하는 행위는 그 앱의 이용약관을 위반할 수 있습니다(계정 정지 등).
> 접근성 서비스는 원래 장애인 보조 목적의 기능이므로, 다른 앱을 몰래 조작하는 용도로 배포하면 구글 플레이 정책에도 위배됩니다.
> 학습·개인용 실험으로 한정하고, 예시 작업도 "설정 열어서 와이파이 켜기"처럼 자신의 기기에서 안전한 것으로 잡으세요.

---

## 전체 구조

```
  사용자: "설정 열어서 와이파이 켜줘"
        │
        ▼
 ┌──────────────┐   ① 화면 상태(UI Tree + 스크린샷) 전달
 │   두뇌(LLM)   │ ◀──────────────────────────────────
 │ Claude/GPT 등 │                                     │
 └──────────────┘   ② "좌표 (540, 1200) 탭" 같은 행동 지시
        │                                              │
        ▼                                              │
 ┌──────────────────────┐   ③ 실제 터치/스크롤 실행      │
 │  안드로이드 앱         │ ───────────────────────────┘
 │  (접근성 서비스)       │   ④ 바뀐 화면을 다시 ①로
 └──────────────────────┘
```

핵심은 이 폴더의 에이전트와 똑같습니다. **LLM은 직접 화면을 만지지 않고, "무엇을 할지"만 정합니다.** 실제 터치는 안드로이드 앱이 합니다. 즉 화면을 만지는 것이 바로 "도구(tool)"입니다.

---

## 핵심 기술: 안드로이드 접근성 서비스 (Accessibility Service)

접근성 서비스는 다른 앱의 **화면 구조(UI Tree)를 읽고**, **터치·스크롤 같은 동작을 대신 수행**할 수 있는 안드로이드 기능입니다. 화면 좌표만 알면 눈 대신 읽고 손 대신 누를 수 있어서, 기기 제어 에이전트의 "눈과 손" 역할을 합니다.

| 역할 | 접근성 서비스 기능 |
|---|---|
| 화면 읽기 (눈) | `getRootInActiveWindow()` 로 현재 화면의 UI Tree 얻기 |
| 요소 정보 | 각 노드의 텍스트, 위치(`getBoundsInScreen`), 클릭 가능 여부 |
| 터치 (손) | `dispatchGesture()` 로 특정 좌표 탭·스와이프 |
| 버튼 동작 | `performAction(ACTION_CLICK)` 등 |

## 구현 단계

### 1단계: 화면 구조를 읽는 기본 앱 만들기
- 안드로이드 스튜디오로 새 앱을 만들고 `AccessibilityService`를 상속한 서비스를 등록합니다.
- 설정 → 접근성에서 이 서비스를 켜면, 다른 화면이 바뀔 때마다 콜백이 호출됩니다.
- `getRootInActiveWindow()`로 화면의 **UI Tree**(텍스트, 레이아웃 구조)를 가져와 로그로 출력해 봅니다.
- *확인 포인트:* 설정 화면을 열었을 때 "Wi‑Fi", "블루투스" 같은 텍스트와 그 좌표가 로그에 찍히는지.

### 2단계: 화면 상태 추출 모듈 올리기
- 오픈소스 기기 제어 에이전트 프레임워크(예: GitHub에서 "android accessibility agent", "mobile use agent" 등으로 검색)를 **참고**하여 구조를 배웁니다.
- 두 가지 형태로 화면 상태를 뽑습니다.
  1. **스크린샷**: `MediaProjection` API로 현재 화면 이미지를 캡처 (비전 기반 모델용).
  2. **좌표 데이터**: UI Tree에서 클릭 가능한 요소들을 `{텍스트, 좌표(x,y), 종류}` 목록(JSON)으로 정리.
- *왜 둘 다?* 텍스트가 있는 요소는 좌표 데이터만으로 충분하지만, 아이콘처럼 텍스트가 없는 요소는 스크린샷이 있어야 LLM이 알아봅니다.

### 3단계: '두뇌(LLM)' 연동
- OpenRouter, OpenAI, Anthropic 등의 API 키를 앱에 연동합니다(키는 앱에 하드코딩하지 말고 안전하게 보관).
- 2단계에서 만든 화면 상태(JSON + 스크린샷)를 LLM에게 보냅니다.
- LLM이 쓸 **도구(tool)**를 정의합니다. 이 폴더의 `tools.py`에서 도구를 정의한 것과 똑같은 개념입니다.

  | 도구 | 설명 | 인자 |
  |---|---|---|
  | `tap` | 특정 좌표를 탭 | `x`, `y` |
  | `swipe` | 스크롤/스와이프 | `x1, y1, x2, y2` |
  | `type_text` | 입력창에 글자 입력 | `text` |
  | `read_screen` | 현재 화면 상태 다시 읽기 | (없음) |
  | `done` | 작업 완료 보고 | `result` |

### 4단계: 시스템 프롬프트로 행동 규칙 설계
LLM에게 "너는 화면을 보고 다음 한 가지 행동을 고르는 에이전트"라고 역할을 줍니다. 예시 흐름:

> 명령: "설정 열어서 와이파이 켜줘"
> 1. `read_screen` → 홈 화면. '설정' 아이콘이 (980, 1850)에 있음.
> 2. `tap(980, 1850)` → 설정 화면으로 이동.
> 3. `read_screen` → 'Wi‑Fi' 항목이 (300, 640)에 있음.
> 4. `tap(300, 640)` → 와이파이 설정 진입, 토글이 꺼져 있음.
> 5. `tap(1000, 300)` → 토글 ON.
> 6. `done("와이파이를 켰습니다")`

이렇게 **한 번에 한 행동 → 화면 다시 읽기**를 반복하는 것이, 이 폴더 `agent.py`의 Tool Runner 루프와 똑같은 구조입니다.

프롬프트에 꼭 넣을 규칙 예시:
- 한 번에 **하나의** 행동만 한다.
- 행동 뒤에는 화면이 바뀌므로 반드시 `read_screen`으로 다시 확인한다.
- 비밀번호 입력, 결제, 앱 삭제처럼 **되돌리기 어려운 행동 전에는 사용자에게 먼저 확인**한다.
- 요청한 작업과 관련 없는 화면이면 멈추고 보고한다.

## 안전장치 (꼭 넣으세요)

- **확인 단계(Human-in-the-loop):** 결제·전송·삭제 등은 실행 전 사용자 승인을 받습니다. (`agent.py`에 도구 실행 전 확인을 넣는 것과 같은 패턴)
- **행동 횟수 제한:** 무한 루프 방지를 위해 최대 행동 수를 둡니다. (`agent.py`의 `max_iterations=10`과 같은 역할)
- **허용 앱 목록:** 조작을 허용할 앱을 화이트리스트로 제한합니다.
- **로그 기록:** 모든 탭·스와이프를 기록해 나중에 검토할 수 있게 합니다.

## 파이썬 예제와의 대응표

| 이 설계(안드로이드) | 이 폴더의 파이썬 예제 |
|---|---|
| 화면을 읽고 터치하는 도구(`tap`, `swipe`) | `tools.py`의 `@beta_tool` 함수들 |
| "한 행동 → 화면 다시 읽기" 반복 | `agent.py`의 Tool Runner 루프 / `manual_loop.py` |
| 행동 규칙을 정하는 시스템 프롬프트 | `agent.py`의 `SYSTEM_PROMPT` |
| 되돌리기 어려운 행동 전 확인 | 도구 실행 전 사용자 확인 추가 |

> 그래서 추천 학습 순서는: **먼저 이 폴더의 파이썬 에이전트로 루프 구조를 완전히 이해 → 그다음 그 구조를 안드로이드 접근성 서비스 위에 올리기** 입니다.
